EmuDecky RomM Manager · UI redesign

Click dummy at Steam Deck resolution (1280×800) plus the implementation spec for romm-emudecky-ng. Chosen variants: drill-down Quick Access Menu, cover grid library, inline readiness strip on the game page. Hover is the gamepad focus. The bottom bar's ··· and B buttons are clickable.

Implementation spec for the coding agent

The prototype above is the source of truth for information architecture, flows and states. It is not a styling reference: build everything with @decky/ui components so focus handling, gamepad navigation and theming (including CSS Loader themes) keep working. All data in the prototype is fake. Real data comes from the existing callables in src/api/backend.ts.

0. Ground rules

  • No feature loss. Every action the plugin has today must still be reachable. This is a re-arrangement, not a rewrite. Reuse existing components and stores (syncProgress, downloadStore, connectionState, saveStatus, updateState, settingsResetStore).
  • Gamepad first. Every interactive element must be reachable with D-pad, A selects, B goes back one level. Keep the existing focus pattern from QAMPanel.tsx (focus the first button after a page change) and BackOnCancel.
  • Keep tests green. Update affected tests, add tests for new components (vitest setup already exists).
  • One PR per phase (see section 5). Each phase must ship a working plugin on its own.
  • Use Decky APIs only: routerHook.addRoute / addPatch, Navigation, showModal, showContextMenu. Do not write shortcuts.vdf directly. Shortcuts and collections stay on SteamClient / collectionStore as today.

2. Quick Access Menu (drill-down)

Keep the existing drill-down model (Page type in QAMPanel.tsx, B on a sub page returns to Home, B on Home closes the QAM). New page set: home | downloads | platforms | settings.

Home, top to bottom

  1. Status line: dot + "Connected · <host>". Reuse ConnectionStatus logic from MainPage.tsx (checking / connected / not connected / backend error / version error).
  2. Library card with an inline state machine instead of separate buttons:
    • idle: "N games · M platforms", "Last sync X ago", primary "Sync library".
    • checking: progress while syncPreview() runs.
    • preview: "+X new · Y updated · Z removed", first few new titles, buttons Apply (syncApplyDelta) and Cancel (syncCancelPreview). Skipped when the "Skip preview" setting is on.
    • running: stage label from the existing STAGE_LABELS + progress bar + Cancel (cancelSync).
    • done: result text from the existing sync delta ("3 added", "Library up to date") + "Sync again".
    "Skip preview" and "Force full sync" move to full-screen Settings.
  3. Needs attention (only rendered when non-empty). One list replacing the scattered banners. Each item navigates to its fix:
    • Save conflict per game → game page, Saves tab, conflict modal open (SyncConflictModal).
    • Required BIOS missing per enabled platform (getFirmwareStatus) → RomM Library, Systems tab.
    • Plugin update available (updateState) → Settings tab, Plugin section.
    • Settings reset notice, playtime scope notice, version error → their existing actions.
  4. Manage rows (drill-down): Downloads (badge with queue count), Platforms & collections, Settings.
  5. Open RomM Library button (full width): Navigation.CloseSideMenus(); Navigation.Navigate("/romm-library").

Sub pages

  • Downloads: compact queue (cover thumb, title, bar, status, pause/resume), "Pause all / Resume all", link "Full queue in RomM Library". Reuse DownloadQueue.tsx logic.
  • Platforms & collections: per-platform sync toggles and collection toggles from today's LibraryPage.tsx. Note "Changes apply on the next sync".
  • Settings (compact): save sync on/off, before launch, after exit, skip sync preview, server host, button "All settings" → full-screen Settings tab. Everything else lives in full screen.

Removed from the QAM: the separate Data Management, System and full Settings pages. Their content moves to the full-screen route.

3. RomM Library (new full-screen route)

// index.tsx, inside definePlugin
routerHook.addRoute("/romm-library", LibraryRoute, { exact: true });
// onDismount
routerHook.removeRoute("/romm-library");

Use the Tabs component from @decky/ui so L1/R1 switch tabs natively. Header: title, connection status, search field (TextField, opens the on-screen keyboard), Sync button. B leaves the route (history back). Remember the last active tab in module state like currentPage in QAMPanel.tsx.

Tab: Library

  • Left rail: "All games" + one entry per platform with count, disabled platforms dimmed. Below: collections.
  • Filter chips with counts: All, Installed, On RomM only, Needs attention.
  • Cover grid, 6 columns at 1280 px (compute columns from width for Big Picture on larger screens). Cover = SteamGridDB/RomM portrait art already used for the shortcut (getArtworkBase / Steam's capsule for the appId).
  • Status badge per cover: installed (green check), on RomM only (cloud), downloading/queued (blue + progress bar along the bottom edge), issue (amber, e.g. save conflict or required BIOS missing).
  • A on a cover opens the Steam game page: Navigation.Navigate(`/library/app/${appId}`). Every synced ROM already has a shortcut appId (getAppIdRomIdMap).
  • Optional quick action on X: download / pause / resume.
  • Data: if no callable returns a merged list (appId, rom id, title, platform, install state, size, issue flags), add one backend callable get_library_overview that joins the metadata cache, installed ROMs, download queue, save status and firmware status. Avoid N calls per cover.

Tab: Downloads

Full queue (active, queued, paused) with pause/resume, start now, cancel, plus a "Finished" list of recent downloads with Open. Reuse DownloadQueue.tsx and downloadStore.

Tab: Systems & BIOS

Table per platform: name + game/installed counts, sync toggle, BIOS status (not needed / ready / missing x/y) with "Download BIOS" (downloadRequiredFirmware), emulator core picker (getPlatformCoreInfo, with the existing CoreChangeModal warning). Keep the Switch firmware row from SystemPage.tsx.

Tab: Settings

Two columns of grouped sections, reusing the existing section components in components/settings/: Connection, Library sync (preferred region, favorites, skip preview, full resync), Artwork & controller (SteamGridDB, Steam Input mode), Save sync, Registered devices, Plugin (version/updates, log level), Danger zone (content of DangerZone.tsx, every destructive action behind ConfirmModal).

4. Game page

  • Primary button (existing CustomPlayButton): Download · size → progress with pause/resume ("Queued · Start now" when queued) → Play. Unchanged behaviour, check the labels match the prototype.
  • Version and disc pickers as compact chips right of the primary button, only when relevant (existing VersionPicker, DiscSelector). Show the current value in the chip ("Europe", "Disc 1", "All discs").
  • Readiness strip (new component, e.g. ReadinessStrip.tsx) directly below the action bar. Three equal chips, each with icon, title, one-line detail and an optional fix button:
    ChipStatesFix action
    ROMinstalled (size · version) / not downloaded (size on RomM) / downloading x% / paused / queuednone, the primary button handles it
    BIOSno BIOS needed (shows core) / ready / missing (warn)"Get" → downloadRequiredFirmware for that platform
    Savessave sync off / synced x ago / on, nothing uploaded yet / conflict (warn)"Resolve" → SyncConflictModal
    Warning chips use the amber treatment. The strip replaces the BIOS stat in the stats row.
  • Play with an unresolved save conflict still opens the conflict modal first (as today), then launches after the choice.
  • Tabs: Overview (existing game info), Saves (slot, local vs server time, version history with restore via savesListFileVersions / savesRollbackToVersion), BIOS & Core (files + per-game core override via setGameCore/clearGameCore), Achievements (unchanged).
  • RomM actions menu (··· button, showContextMenu with MenuSeparator): groups "Game" (refresh artwork, refresh metadata, choose SteamGridDB artwork, Steam Input mode), "Saves" (sync now, save history), "Remove" (delete local saves…, uninstall ROM…). Remove items only when installed, both behind ConfirmModal that states what is kept (shortcut, playtime, saves on RomM).
  • Add a small button "Show in RomM Library" that opens the route filtered to the game's platform.
  • Keep the injection slim. This patch is the part most likely to break on Steam client updates.

5. Phases (one PR each)

  1. Route skeleton: register /romm-library with Tabs. Move Settings, Danger zone and System page content into the Settings and Systems tabs. QAM gets the "Open RomM Library" button. Old QAM sub pages may stay until phase 2.
  2. QAM home: status line, Library card state machine, Needs attention list, Manage rows, compact Downloads/Platforms/Settings sub pages. Remove the old QAM pages.
  3. Game page: readiness strip, pickers as chips, grouped actions menu with confirms, Saves and BIOS & Core tabs.
  4. Library grid: get_library_overview callable, platform rail, filters, search, cover grid with badges, Downloads tab.

6. Done criteria

  • Every flow in the prototype works with only D-pad, A, B, L1/R1 on a real Deck in Game Mode, and in Big Picture on a desktop.
  • No dead ends: B always returns to the previous level, focus never gets lost after closing a modal.
  • Offline (RomM unreachable): QAM shows "Not connected", sync/download actions disabled with a reason, installed games still launch.
  • All existing features reachable (check against the README feature list and the user guide in docs/user-guide/). Update the docs and screenshots.
  • Lint, type check and tests pass.

7. Out of scope

  • Adding tabs to Steam's own library page (leave that to TabMaster, keep collections clean so it can filter by them).
  • An entry in Steam's main menu.
  • Changes to sync, download or save logic in the backend beyond the one overview callable.
