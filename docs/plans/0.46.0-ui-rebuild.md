# Plan: 0.46.0–0.50.0 — UI rebuild

Tracker #38; phase issues #78 (0.46.0), #79 (0.47.0), #80 (0.48.0), #81 (0.49.0), #82 (0.50.0).
Status: **plan; order and adjustments confirmed by Patrick 2026-11-10.**

## 1. Source of truth

`docs/design/ui-redesign-prototype.html`: click dummy (1280×800) plus the implementation spec (§0–§7). The prototype
defines information architecture, flows and states, not styling: everything is built with `@decky/ui` so gamepad focus
and CSS Loader themes keep working. Surfaces: drill-down QAM (glance and quick actions), new full-screen route
`/romm-library` (Tabs: Library, Downloads, Systems & BIOS, Settings), game page (readiness strip, chips, actions menu).

## 2. Order (one PR and one real minor per phase)

| Version | Phase |
| ------- | ----- |
| 0.46.0 | Route skeleton with tabs, Settings/Danger/System move in, QAM button, **`get_library_overview` callable (pulled forward)** |
| 0.47.0 | QAM home: status line, Library card state machine, Needs attention, compact sub pages; old QAM pages removed |
| 0.48.0 | Game page before the grid: the Steam injection is the riskiest part, so it is device-tested early |
| 0.49.0 | Library grid (rail, filters, search, badges) and Downloads tab (#40); pure UI, the callable already exists |
| 0.50.0 | Done criteria (spec §6), docs, screenshots, remove old components |

## 3. Decisions (Patrick, 2026-11-10)

1. Order as above, game page (0.48) before the grid (0.49); the overview callable moves to 0.46.
2. Save-sync UI (conflict modal, Saves tab, history/rollback, registered devices, attention items) is built now and shows
   the unavailable/not-implemented state until 0.55.0 (no invented numbers; Saves chip says planned).
3. Switch-only: the Systems & BIOS table is generic but shows the Switch row until 0.80.0.
4. "Lint" in the spec's done criteria becomes: typecheck and tests green, no new TS warnings in the build (no lint in CI by decision).
5. 0.45.0 was closed first (tag `v0.45.0`); device checks of firmware downloads and the Bazzite layout remain open.

## 4. Risks

- Steam injection (phase 3) can break on client updates: keep it slim, test on the device per step.
- Two focus models (route and QAM): every phase gets a focus test (B goes one level back, focus restored after modals).
- ~1,560 frontend tests: components move rather than get rewritten; the tests are the "no feature loss" measure.

## 5. Progress notes

- **0.46.0 (phase 1):** `/romm-library` route with Tabs (Library, Downloads, Systems & BIOS, Settings = settings + danger
  zone), last tab remembered, QAM button "Open RomM Library", callable `get_library_overview` (bound ROMs by name with
  install state, per-platform counts, `download` merged from the queue; `issues` stays empty until save sync). The
  Library tab shows only counts until the grid (0.49.0). The moved pages keep their own "Back" button (leaves the
  route); the header (connection status, search, Sync) and restyling for full screen come with the later phases.
- **0.47.0 (phase 2):** QAM home = status line (dot + host), Library card (stats, sync with preview/running/done,
  "Sync Again" after a finished run, reason text when offline), Needs attention (settings-reset, playtime-scope and update
  banners moved into one section, plus "Switch keys missing" which opens the Systems tab), Manage rows (Downloads with count,
  Platforms & collections, Settings) and Open RomM Library. QAM pages are now home | downloads | platforms | settings; System,
  Data Management and the full Settings page are gone from the QAM (they live in the route). Compact Downloads page (Pause all /
  Resume all, link to the full queue), compact Settings (save sync toggles, skip preview, host, All settings). **Skip preview**
  has no backend setting, so it is a frontend preference in localStorage (`utils/syncPreferences.ts`), shared by the QAM and the
  Settings tab; "Force full sync" moved to the Settings tab with it. Save-sync items show "not implemented yet" until 0.55.0.
  The version-error card still replaces the whole home. Not in this phase: save-conflict items in Needs attention (save sync
  is unported), the Library card's inline "first new titles" preview (the existing preview summary is kept).
- **0.48.0 (phase 3):** game page. Readiness strip (`ReadinessStrip.tsx`, texts in `utils/readiness.ts`) under the play row:
  ROM (installed / queued / downloading x% / paused / interrupted, live from the download store), BIOS (Switch: missing required
  keys with "Get" = `download_required_firmware`; other platforms "No BIOS needed" plus the core), Saves (off / synced x ago /
  on / conflict with "Resolve" = the existing conflict modals). Disc and version pickers are chips that show their value
  ("Disc 2", "All discs", the version label). RomM actions menu is grouped: Refresh artwork/metadata, then Sync save files and Save
  history (opens the SAVES tab), then, only for an installed ROM, Delete local saves… and Uninstall ROM…, both behind a
  ConfirmModal that says what is kept. New "Show in RomM Library" button (opens the route's Library tab narrowed to the platform).
  Info tabs: OVERVIEW (was GAME INFO), SAVES, BIOS & CORE (keys per emulator with a one-tap download, active emulator with the
  per-game override through `utils/gameCore.ts`). **Deferred (not in the spec's first cut, need backend or belong elsewhere):**
  "Download · size" on the primary button and "Start now" for a queued download (no `move_to_front` callable yet, #40),
  "Choose SteamGridDB artwork" and a per-game Steam Input mode in the menu, the Achievements tab (does not exist today).
  The play section's own core menu keeps its separate implementation next to the shared `changeGameCore` (follow-up: merge them).
- **0.49.0 (phase 4):** Library tab = platform rail (name and count, platforms with sync off marked), filter chips with counts
  (All / Installed / On RomM only / Needs attention), search, and a cover grid (`LibraryGrid.tsx`, logic in `utils/libraryGrid.ts`).
  Covers are Steam's custom portrait art (`steamloopback.host/customimages/<appId>p.png`, falls back to the name); badges for
  installed, on RomM only, downloading / queued / paused (progress bar on the bottom edge), issue. A opens the Steam game page,
  X downloads / pauses / resumes. The badges follow the live queue; the grid refreshes after a sync, a finished download and an
  uninstall. The Downloads tab got "Open" on finished ROMs. **Not in this phase:** the collections rail (the overview has no
  collection membership yet), "Start now" and reorder in the queue (no `move_to_front` callable; #40 stays open for it).
  **No-scroll rule (device finding after 0.48.0):** information `Field`s are now `focusable` everywhere, because the Steam UI
  cannot scroll and the cursor only stops on focusable elements (see CLAUDE.md).
