## Progress (2026-11-10/11)

- ADR-0023 merged with the device facts (Deck, Bazzite): title ID order incl. learning from play, role-rooted zip entries,
  profile rules, Ryujinx restore only into an existing index, RomM's per-entry zip hash.
- Domain: `save_archive`, `switch_save`, `sync_action` (differentially tested against the Python reference), `rom_save_state`,
  `save_status`. Adapters: `switch_save_files` (Eden/yuzu/Ryujinx), `RommSavesApi`, `SqliteSaveState`, `SqliteTitleIds`,
  migration 015. Service: `SaveService` with all 22 save callables plus `get_save_title_info`, `set_save_title_id`,
  `set_save_profile`; the "not implemented" mechanism (`unportedCallable`) is removed.
- Frontend: the save callables are real; the Saves chip offers **Choose** (save folder / profile) through `SaveSetupModal`.
- Tests: service tests against a simulated RomM (device sync rows, the write-time 409), real-socket tests with a fake RomM,
  frontend tests; mutation-checked safety rules (which found two real bugs: baselines not cleared on a slot change, and a
  Ryujinx backup read as a second save index).

## Still open

- Eden profile listing shows names from `profiles.dat`; the "learned from play" proposal needs a real session to confirm.
- Follow-ups: a per-game restore of an update/DLC title, and the Saves tab wording for slots (UI review).
