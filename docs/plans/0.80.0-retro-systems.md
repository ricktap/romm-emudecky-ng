# 0.80.0 — retro systems (#49–#54): plan

Goal: games of the systems from Atari to the N64 era launch from Steam on the first try, on the Deck and on Bazzite,
through EmuDeck. 1.0.0 comes after 0.80.0 and 0.90.0 (decided 2026-11-11).

## Where we start

- Our own emulator table (`domain/emulator_table.rs`) covers **Switch only**: each entry is a locate glob under `$HOME`
  plus an args template whose last token is the ROM. The shortcut's exe stays `rom-launcher-ng`; `launch_options` carries
  the full command (D2/D4).
- `defaults/config.json` already maps 149 RomM slugs to local folder names (`platform_map`). The roms folders EmuDeck
  creates are not verified against it.
- The per-game override, the per-platform default and the "only installed emulators can be chosen" rule already work on
  the table and do not change.
- EmuDeck facts known so far (Deck, 2026-11-08): `~/Applications` holds the standalone AppImages; **RetroArch and Dolphin
  are flatpaks**, RetroArch cores live in `~/.var/app/org.libretro.RetroArch/config/retroarch/cores`.

## Design (for approval before any code)

### 1. Two kinds of table entry

| Kind | Located by | Command | Example |
| --- | --- | --- | --- |
| standalone (today) | glob under `$HOME` | `<exe> <args with {rom}>` | `Applications/DuckStation*.AppImage` |
| **retroarch (new)** | the RetroArch flatpak data folder exists **and** the core file `<core>_libretro.so` exists in its `cores/` folder | `flatpak run org.libretro.RetroArch -L <cores>/<core>_libretro.so "{rom}"` | SNES → `snes9x` |

- Every RetroArch core is **its own picker entry** ("Snes9x (RetroArch)", "bsnes (RetroArch)"). That reuses the per-game
  override and the platform default unchanged, and "installed" simply means the core file is there.
- Per system the table lists emulators in preference order; the default is the first installed one (same rule as Switch).
- No `vblank_mode=0` prefix for flatpak RetroArch (it is a Mesa setting for the standalone AppImages).
- The command goes through `rom-launcher-ng` like everything else; EmuDeck's own launcher scripts stay out of the chain.

### 2. Slug mapping (#50)

- A test file with a table of RomM slugs → EmuDeck roms folder for every retro system, **checked against the real folder
  list** from a Deck (below). Unknown slugs keep the verbatim fallback only inside the ROM root with the traversal guard.
- Acceptance: every platform enabled in the UI resolves to a folder that exists in EmuDeck's `Emulation/roms`.

### 3. Order of work

1. **Facts from your machines** (below) → fill the table and the mapping test from what is really installed.
2. #49: table entries for the retro systems + the RetroArch kind, with unit tests for locate, command rendering,
   precedence and override; integration test like the Switch ones.
3. #50: slug table test.
4. Your on-device acceptance per system (a checklist per system, like the Switch one).
5. Then #51 (core selection UI, input-driver fix, save-compat prompts), #52 (discs / M3U), #54 (classic BIOS +
   RetroAchievements; needs a decision on scope), #53 (RetroArch save sync).
